## 📌 О проекте

Спрос на недвижимость — ключевой индикатор состояния экономики и основной фактор, определяющий
динамику цен и инвестиционную привлекательность рынка. Точный прогноз спроса позволяет
регуляторам, инвесторам и девелоперам принимать обоснованные решения по планированию
строительства, инвестициям и управлению рисками.

Мы решаем **задачу регрессии**: предсказать общий спрос на недвижимость в **районах Лондона**
на основе исторических и текущих данных.

| | |
| --- | --- |
| **Регион исследования** | Районы Лондона, Великобритания |
| **Тип задачи** | Регрессия (ML → DL) |
| **Целевая переменная** | Количество сделок с недвижимостью — аренда, ипотека, покупка в собственность |
| **Признаки** | Макроэкономические, демографические, рыночные, пространственные; тональность новостей (NLP) |

## ⚙️ Окружение

Зависимостями и виртуальным окружением управляет [uv](https://docs.astral.sh/uv/). Версия
Python зафиксирована в `.python-version`, точные версии пакетов — в `uv.lock`.

Установка uv (macOS и Linux):

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh   # официальный установщик
wget -qO- https://astral.sh/uv/install.sh | sh    # если нет curl
brew install uv                                   # вариант для macOS
uv self update                                    # обновить uv (кроме установки через brew)
```

Сам Python ставить не нужно: `uv sync` скачает версию из `.python-version`.

Работа с окружением:

```bash
uv sync                      # создать .venv и поставить всё из uv.lock
uv sync --group notebooks    # + JupyterLab и ядро для исполнения ноутбуков
uv run jupyter lab           # открыть ноутбуки в браузере (после uv sync --group notebooks)
uv run <команда>             # запуск в окружении без активации .venv
uv add <пакет>               # добавить зависимость (сам обновит pyproject.toml и uv.lock)
uv remove <пакет>            # удалить зависимость (из pyproject.toml, uv.lock и .venv)
uv remove --group notebooks <пакет>   # удалить из группы, а не из основных зависимостей
```

Код проекта лежит в пакете `lpdf` и ставится в окружение editable-режимом, так что
`from lpdf... import ...` работает одинаково в ноутбуках, скриптах обучения и сервисе.

Ноутбуки можно открывать как в JupyterLab (`uv run jupyter lab`), так и плагином VS Code:
*Select Kernel* → *Python Environments* → `.venv`.
Ставить что-либо по подсказке VS Code не нужно — всё ставится через `uv add`, иначе
окружение разъедется с `uv.lock`.

## ✅ Проверки перед коммитом

Код проверяется [pre-commit](https://pre-commit.com): на `git commit` по изменённым файлам
прогоняются `ruff` (линтер и форматтер Python), `shellcheck` (загрузчики на bash) и набор
базовых проверок — лишние пробелы, перенос в конце файла, следы конфликтов, случайный
коммит большого файла. Список хуков — в `.pre-commit-config.yaml`.

> [!IMPORTANT]
> Хук живёт в `.git/`, с клоном он не приезжает. После `uv sync` его нужно поставить
> **один раз на каждой тачке**, иначе проверки будут молча не работать:

```bash
uv run pre-commit install                      # поставить git-хук (один раз на тачке)
uv run pre-commit autoupdate                   # обновить версии хуков
```

Прогнать проверки вручную, не делая коммит:

```bash
uv run pre-commit run --all-files              # по всему репозиторию
uv run pre-commit run                          # только по файлам из git add
uv run pre-commit run --files README.md        # по конкретным файлам
uv run pre-commit run ruff-format --all-files  # один хук по имени из конфига
uv run pre-commit run --all-files --show-diff-on-failure   # показать, что именно хук переписал
```

Если хук изменил файлы (например, убрал пробелы), коммит не создаётся: нужно проверить
правки, сделать `git add` и повторить `git commit`.

Линтер и форматтер можно вызвать напрямую — `uv run ruff check .`, `uv run ruff format .`.
Версия ruff при этом берётся из dev-группы `pyproject.toml`, а не из `rev` в
`.pre-commit-config.yaml`; сейчас они совпадают, но после `pre-commit autoupdate` могут разъехаться.

## 📂 Структура репозитория

```
london-property-demand-forecast/
├── src/lpdf/                                # код проекта
├── primary-data/                            # первичные данные
│   ├── loaders/                             # загрузчики из источников
│   │   └── <источник>/                      # имя источника в качестве имени загрузчика
│   │       └── README.md                    # инструкция как пользоваться загрузчиком
│   ├── README.md                            # источники данных
│   └── DB.md                                # БД первичных данных
├── notebooks/                               # ноутбуки ipynb
│   └── EDA.ipynb                            # разведочный анализ
├── docs/                                    # документы проекта
│   └── practical-value.md                   # практическая ценность проекта (md)
├── pyproject.toml                           # метаданные проекта и зависимости
├── .pre-commit-config.yaml                  # проверки перед коммитом
├── uv.lock                                  # зафиксированные версии пакетов
├── .python-version                          # версия Python для uv
├── .gitignore
└── README.md
```

> [!IMPORTANT]
> У каждого загрузчика свой `README.md` с инструкцией по запуску. В
> [списке источников](primary-data/README.md) — только описание данных и ссылка
> на эту инструкцию, чтобы он не разрастался по мере добавления источников.
