# Bank of England — все ряды публичного каталога, raw CSV

Один загрузчик для [интерактивной базы Bank of England](https://www.bankofengland.co.uk/boeapps/database/).
Он получает **все ряды публичного каталога**, их описания и полную опубликованную историю.
Ручного списка показателей, отбора по теме, стране, сезонности, частоте или годам нет.
Прежний `series.json` с семью показателями больше не используется.

Область выгрузки — именно интерактивная база. Отдельные публикации BoE в Excel, например
Mortgage Lenders and Administrators Statistics (MLAR), автоматически в неё не входят.
Это агрегированная статистика источника; отдельных ипотечных договоров загрузчик не получает.

Источник: [каталог](https://www.bankofengland.co.uk/boeapps/database/),
[документация CSV/XML](https://www.bankofengland.co.uk/boeapps/database/help.asp),
[условия использования](https://www.bankofengland.co.uk/legal). Атрибуция: Bank of England.

Для базы действует OGL v3.0 с указанными BoE исключениями: отдельные валютные ряды
воспроизводятся по лицензиям третьих лиц. Для SONIA предусмотрена специальная
атрибуция. Полная raw-выгрузка сохраняет все ряды; условия их дальнейшего
распространения нужно читать в разделе `Bank of England Database` по ссылке выше.

## Как получается полный каталог

1. Загрузчик читает все варианты частоты из формы расширенного поиска самого BoE.
2. Для каждой частоты проходит все страницы и сверяет коды с числом результатов сервера.
   Интерфейс показывает только первые 16 кнопок страниц; загрузчик передаёт полный список
   смещений в ту же форму и проверяет номер страницы, границы выдачи и отсутствие повторов.
3. Для каждого полученного кода скачивает XML с описанием, единицами, частотой, примечаниями
   и датами первого и последнего наблюдения. Исторические ряды не исключаются.
4. Запрашивает исходный CSV `CSVF=CN` за весь опубликованный период каждого ряда.
   Обычные CSV-порции содержат не более 50 кодов, дневные — не более 20.
   При сбое большие запросы делятся на части. Это разбиение для передачи, а не отбор данных.
5. Проверяет покрытие всех кодов, непрерывность запрошенных интервалов, фактические первую
   и последнюю даты. Коды без наблюдений по XML сохраняются в каталоге и учитываются отдельно.
   Неудавшийся запрос не считается пустым рядом, неполный снимок не загружается в БД.

Запрос XML `SeriesCodes=all` возвращает только ряды, **добавленные** в указанный период,
а крупные интервалы при проверке возвращали HTTP 500. Поэтому каталог собирается по
публичной поисковой выдаче с проверкой количества записей, а XML запрашивается по кодам.

Каталог, полученный 17 октября 2026 года: **37 012 рядов**.
Это число кодов, а не количество наблюдений в CSV.

| Частота BoE | Код | Число рядов |
| --- | --- | ---: |
| День | `D` | 376 |
| Неделя, среда | `W3` | 99 |
| Неделя, четверг | `W4` | 10 |
| Месяц | `M` | 8 602 |
| Квартал, февраль/май/август/ноябрь | `P` | 75 |
| Календарный квартал | `Q` | 20 836 |
| Полугодие | `B` | 2 850 |
| Календарный год | `A` | 4 002 |

Полная выгрузка этого каталога содержит **5 163 002 наблюдения в 762 CSV-файлах**.
У всех 37 012 рядов есть наблюдения. Общие границы опубликованной истории —
**31 марта 1963 — 15 октября 2026**, у каждого ряда свой период.
Объём CSV — около 139 МБ; все исходные ответы вместе с XML и HTML — около 246 МБ.

при следующем запуске состав и значения могут измениться.

## Столбцы таблицы и единицы

Таблица: `"primary".bank_of_england__raw`. Одна строка — одно наблюдение одного ряда.
Это исходный формат CSV BoE; загрузчик не разворачивает широкую таблицу самостоятельно.

| Колонка | Что означает | Единица / формат |
| --- | --- | --- |
| `DATE` | Дата, которой источник обозначает наблюдение; для периодических рядов представляет весь период, а не обязательно отдельный день | Исходная строка `DD Mon YYYY`, например `31 Jan 2023`; период задают `FREQ_CODE` / `FREQ_NAME` в XML |
| `SERIES` | Идентификатор показателя в BoE; соответствует `SCODE` в XML. Другая частота, сезонная корректировка или вид показателя могут иметь другой код | Код без единицы, например `IUMABEDR`; не название колонки и не код района |
| `VALUE` | Опубликованное значение показателя на дату; смысл определяется конкретным рядом | Проценты, суммы в заданной валюте и масштабе, количество, индексы, курсы и другие единицы; смотреть `DESC`, `CONCAT` и категорию `OUTPUT IN` в XML |

Все три колонки в PostgreSQL имеют тип `text`. Сохраняются исходные строки чисел, даты,
пустые значения, обозначения `..` и повторяющиеся строки. Пустое значение не заменяется нулём.
`..` у BoE означает недоступное или скрытое по конфиденциальности значение.
Ключа уникальности по дате и коду нет: исходные повторы не удаляются.

Например, `IUMABEDR` — месячная средняя ключевой ставки (`Monthly average of official
Bank Rate`), единица — процент. Это определение одного ряда, а не всей колонки `VALUE`.
Значения разных кодов нельзя складывать или сравнивать без проверки их единиц.

Расчётов, заполнения пропусков, пересчёта единиц, агрегации по месяцам, объединения
с Nomis и подготовки признаков нет. Сезонно скорректированные значения и темпы роста,
если они опубликованы самим BoE, сохраняются как отдельные исходные ряды.

## Где читать описание показателя

Исходные файлы `metadata_*.xml` сохраняются целиком. В них:

| Поле / атрибут XML | Смысл | Формат / единицы |
| --- | --- | --- |
| `SCODE` | Код ряда, соответствующий `SERIES` в CSV | Текст |
| `DESC` | Полное название показателя | Текст источника |
| `COUNTRY` | Страна или географический агрегат, если указан источником | Текст; пустое поле само по себе не означает Великобританию |
| `CONCAT` | Объединённое описание категорий ряда | Текст источника |
| `FREQ_NAME`, `FREQ_CODE`, `FREQ_ORD` | Название, код и порядок частоты | Например `Monthly`, `M`; порядок — служебный атрибут BoE |
| `FIRST_OBS`, `LAST_OBS` | Первая и последняя опубликованные даты | `YYYY-MM-DD`; обе пустые, если наблюдений нет |
| `CAT_NAME`, `CAT_VAL`, `VAL_DESC`, `CAT_ORD` | Название категории, код, расшифровка и порядок | В частности `OUTPUT IN` задаёт единицы, `SEASONAL ADJUSTMENT` — сезонную корректировку |
| `SERIES_DEF`, `DEF_LOC` | Описание методологии и ссылка на него | Текст / URL |
| `SERIES_COM` | Примечания к ряду | Текст источника, в том числе изменения методологии |

В `manifest.json` есть индекс `series` для быстрого поиска кода, список исходных файлов,
URL запросов, SHA-256, список частот, количество записей и статус загрузки. Это технический
учёт выгрузки; исходные XML остаются рядом и в таблицу наблюдений служебные поля не добавляются.
Предварительные значения включены (`VPD=Y`). CSV содержит текущую публикацию значений,
а не историю всех прошлых пересмотров. Номер снимка не означает единый момент публикации BoE:
отдельные ответы скачиваются последовательно; существенные изменения покрытия приводят к ошибке.

## Запуск из корня репозитория

Используется окружение проекта на Python 3.14 через [uv](../../../README.md).
`--with-requirements` подключает зависимости загрузчика из `requirements.txt`
на время запуска; общие зависимости проекта не меняются.

Для загрузки в БД нужен PostgreSQL и драйвер из `requirements.txt`. Docker не нужен.

```powershell
# Весь каталог, XML и CSV; подключения к БД нет.
uv run --with-requirements primary-data/loaders/bank-of-england/requirements.txt python primary-data/loaders/bank-of-england/load.py --download-only

# Продолжить прерванную выгрузку. Подставить путь, напечатанный первым запуском.
uv run --with-requirements primary-data/loaders/bank-of-england/requirements.txt python primary-data/loaders/bank-of-england/load.py --resume primary-data/loaders/bank-of-england/data/<snapshot> --download-only

# Загрузить готовый снимок только в локальную БД.
uv run --with-requirements primary-data/loaders/bank-of-england/requirements.txt python primary-data/loaders/bank-of-england/load.py --snapshot primary-data/loaders/bank-of-england/data/<snapshot> --env-file primary-data/loaders/bank-of-england/data/local-check/local.env --local-only
```

`--workers` принимает от 1 до 8 (по умолчанию 2), `--batch-size` — от 1 до 300. Эти параметры меняют только
размер и параллельность запросов; обычные CSV-порции ограничены 50 кодами,
дневные — 20, XML-порции — 25 кодами. Эти размеры уменьшают число таймаутов BoE.
Слишком длинные URL дополнительно делятся на части.
При продолжении используйте прежний `--batch-size`, чтобы переиспользовать те же CSV-порции;
XML переиспользуется и при изменении размера порций. При принудительном завершении процесса
до семи последних CSV-ответов могут потребовать повторного скачивания.
Фильтров `--from-year` / `--to-year` нет. Период определяется метаданными каждого ряда;
если источник укажет историю до поддерживаемого CSV endpoint 1963 года, загрузчик остановится,
а не обрежет её молча. Снимки прежнего формата из семи колонок не подходят для `--snapshot`.

## Подключение и замена таблицы

Общие правила подключения — в [DB.md](../../DB.md), общие параметры команды — в
[db.env](../../db.env). Файл `db.env` содержит Bash-команды: его подключают через
`source primary-data/db.env` в Bash, а не передают в `--env-file`.

`--env-file` принимает обычные строки `PGHOST=...`, `PGPORT=...`, `PGDATABASE=...`,
`PGUSER=...`, `PGPASSWORD=...`, `PGSSLMODE=...` без `export` и кавычек; они имеют приоритет
над переменными окружения. Пароли и скачанные данные не должны попадать в Git.

Для локальной проверки используется отдельный игнорируемый файл
`data/local-check/local.env`: адрес `127.0.0.1`, порт локального PostgreSQL и имя локальной БД.
Создайте этот файл со своими локальными параметрами; общую `.env` рабочей БД не подставляйте.
`--local-only` отклоняет адреса вне loopback. Саму БД создают заранее.

После проверки снимка строки копируются во временную таблицу. Замена целевой таблицы
выполняется одной транзакцией; ошибка откатывает изменения. Повторный запуск заменяет данные,
не накапливая копии. Другие источники не затрагиваются.

Для BoE остаётся одна постоянная таблица: `"primary".bank_of_england__raw`.
При переходе со старого формата из восьми колонок загрузчик заменяет старую таблицу
новой из трёх колонок в той же транзакции, после проверки и подготовки всех данных.
Резервные таблицы не создаются; временная таблица удаляется при завершении транзакции.
При ошибке возвращаются прежняя структура и данные. Неизвестная схема существующей
таблицы приводит к ошибке без её замены.

## Перенос готовой локальной таблицы без API

`transfer.py` переносит только `"primary".bank_of_england__raw` из локального
PostgreSQL в рабочий. Повторных запросов к BoE нет. Структура остаётся исходной:
три колонки `DATE`, `SERIES`, `VALUE`, тип `text`; значения и повторы не меняются.

Из корня репозитория:

```powershell
# Сверить обе базы без записи.
uv run --with-requirements primary-data/loaders/bank-of-england/requirements.txt python primary-data/loaders/bank-of-england/transfer.py --source-env primary-data/loaders/bank-of-england/data/local-check/local.env --target-env primary-data/.env --snapshot primary-data/loaders/bank-of-england/data/<snapshot> --check-only --report primary-data/loaders/bank-of-england/data/local-check/transfer-check.json

# Перенести полную локальную таблицу в рабочую схему primary.
uv run --with-requirements primary-data/loaders/bank-of-england/requirements.txt python primary-data/loaders/bank-of-england/transfer.py --source-env primary-data/loaders/bank-of-england/data/local-check/local.env --target-env primary-data/.env --snapshot primary-data/loaders/bank-of-england/data/<snapshot> --report primary-data/loaders/bank-of-england/data/local-check/working-transfer.json
```

`--source-env` и `--target-env` содержат буквальные строки `PG*=значение`, как описано
выше. Исходный сервер должен быть локальным; одинаковые исходная и целевая БД
отклоняются. Снимок нужен для проверки полноты: файлы, каталог, ожидаемые колонки,
количество строк и периоды. Переносимые значения берутся непосредственно из БД.

Скрипт читает локальную таблицу в `REPEATABLE READ READ ONLY`, порциями по 25 000
строк. `--batch-size` задаёт размер порции от 1 000 до 100 000. На обоих серверах
сверяются количество строк и четыре точные суммы 64-битных частей SHA-256 от
UTF-8 JSON-массива каждой строки. В проверке участвуют все поля, NULL, пустые
строки и повторения, порядок строк не важен. Совпавшая таблица пропускается.

Отличающиеся данные сначала попадают во временную таблицу. После совпадения её
контрольной суммы заменяется целевая таблица и проверяется результат, всё в одной
транзакции. Старый формат из восьми колонок заменяется на три; неизвестная структура
отклоняется. Постоянная таблица остаётся одна. При ошибке прежние данные сохраняются;
повторный запуск передаёт незавершённую таблицу заново. Меньшее количество строк
и потеря существующих периодов нового формата запрещены. На сервере нужно место
для временной копии и журнала PostgreSQL. Во время передачи блокируется запись
в старую таблицу; чтение остаётся доступно до этапа замены.

JSON-отчёт содержит количества, контрольные суммы и статус `copied` / `identical`
(в режиме проверки — также `different` / `missing`), без паролей. Общий механизм
переноса находится в `../nomis/_postgres_transfer.py`; команда BoE не обращается
к таблицам или API Nomis. Проверки этого механизма описаны в
[README Nomis](../nomis/README.md#проверки).

## Проверки

```powershell
# Без сети и без БД: каталог, пагинация, целостность снимков, исходные значения, продолжение загрузки.
uv run --with-requirements primary-data/loaders/bank-of-england/requirements.txt python -m unittest discover -s primary-data/loaders/bank-of-england/tests -p test_loader.py -v

# Миграция, повторы, сохранение текста и откат ошибок во временной локальной БД.
uv run --with-requirements primary-data/loaders/bank-of-england/requirements.txt python primary-data/loaders/bank-of-england/tests/check_local.py --env-file primary-data/loaders/bank-of-england/data/local-check/local.env

# Сверить готовую локальную таблицу со всеми CSV; только чтение.
uv run --with-requirements primary-data/loaders/bank-of-england/requirements.txt python primary-data/loaders/bank-of-england/tests/check_local.py --env-file primary-data/loaders/bank-of-england/data/local-check/local.env --snapshot primary-data/loaders/bank-of-england/data/<snapshot> --verify-existing
```

Сверка проверяет имена и типы колонок, число строк и независимую от порядка сумму
SHA-256 каждой строки по каждому ряду, включая пустые значения и дубли.
Для создания временной тестовой БД нужны права `CREATEDB`; после проверки она удаляется.

Для полного снимка от 17 октября 2026 года сверка с локальным PostgreSQL прошла:
все 5 163 002 строки совпали с CSV, включая 5 042 исходных значения `..`.
Фактический размер единственной таблицы BoE в локальном PostgreSQL, включая служебные
структуры: **301 719 552 байта — 301,72 МБ / 0,302 ГБ** (287,74 МиБ).
Размер таблицы может отличаться на другом сервере и после следующих загрузок.

```sql
SELECT * FROM "primary".bank_of_england__raw LIMIT 20;
SELECT "SERIES", count(*) FROM "primary".bank_of_england__raw GROUP BY "SERIES" ORDER BY "SERIES";
```

Исходные имена колонок в SQL заключаются в двойные кавычки. Выгрузка BoE, её тесты
и данные находятся в `bank-of-england/`. Только прямой перенос между БД использует
общий модуль PostgreSQL из папки Nomis; правила получения данных источников разделены.
