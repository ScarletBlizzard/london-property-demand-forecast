# Bank of England

Загрузчик скачивает все ряды [публичной интерактивной базы BoE](https://www.bankofengland.co.uk/boeapps/database/):
ставки, кредитование, ипотеку, валютные курсы и другие финансовые показатели.
Берётся вся опубликованная история, без отбора по теме, стране, частоте или годам.
Отдельные Excel-публикации вне этой базы не входят в выгрузку.

Результат — одна таблица **`"primary".bank_of_england__raw`**. Все поля имеют тип `text`:
числа, даты, пропуски и повторы сохраняются как у источника. Загрузчик ничего не рассчитывает.
В снимке от 17.10.2026: **37 012 рядов и 5 163 002 строки**, история с 31.03.1963 по 15.10.2026.

## Столбцы таблицы

Одна строка — значение одного показателя за одну дату или период.

| Столбец | Что означает | Единица / формат |
| --- | --- | --- |
| `DATE` | Дата наблюдения. Для месячного или годового ряда обозначает соответствующий период | Текст, например `31 Jan 2023`; частота указана в XML |
| `SERIES` | Код показателя BoE; по нему можно найти описание и единицу измерения | Код, например `IUMABEDR`; совпадает с `SCODE` в XML |
| `VALUE` | Опубликованное значение показателя | Зависит от ряда: %, GBP и другие валюты, количество, индекс, валютный курс и т. д. |

У `VALUE` нет общей единицы для всей таблицы. Например, `IUMABEDR` — средняя за месяц
ключевая ставка в процентах. У денежных показателей нужно проверить и валюту, и масштаб
(единицы, тысячи, миллионы). Пустое поле и `..` означают отсутствие доступного значения, а не ноль.

## Где найти описание и единицы показателя

Вместе с CSV сохраняются файлы `metadata_*.xml` в `data/<snapshot>/`.
Описание связывается с таблицей по **`SERIES = SCODE`**.

| Поле XML | Что означает |
| --- | --- |
| `SCODE` | Код показателя |
| `DESC`, `CONCAT` | Название и описание показателя |
| `COUNTRY` | Страна или географический агрегат, если указан |
| `FREQ_CODE`, `FREQ_NAME` | Код и название частоты: день, неделя, месяц, квартал и т. д. |
| `FIRST_OBS`, `LAST_OBS` | Первая и последняя даты наблюдений, `YYYY-MM-DD` |
| Категория `OUTPUT IN` | Единицы и масштаб значения; категории описаны полями `CAT_NAME`, `CAT_VAL`, `VAL_DESC` |
| Категория `SEASONAL ADJUSTMENT` | Наличие сезонной корректировки у исходного ряда |
| `SERIES_DEF`, `DEF_LOC`, `SERIES_COM` | Методология, ссылка на неё и примечания |

`manifest.json` содержит каталог рядов, список файлов и результат проверки полноты.
Это служебный файл выгрузки, его поля в таблицу не добавляются.

## Как запустить

Нужны Python 3.14, `uv` и PostgreSQL. Команды выполняются из корня репозитория.
Параметры подключения описаны в [DB.md](../../DB.md), общие настройки — в [db.env](../../db.env).
Для Python параметр `--env-file` принимает обычный файл со строками
`PGHOST=...`, `PGPORT=...`, `PGDATABASE=...`, `PGUSER=...`, `PGPASSWORD=...`, `PGSSLMODE=...`
без `export` и кавычек. Bash-файл `db.env` напрямую в этот параметр не передаётся.

Скачать CSV и XML без записи в БД:

```powershell
$loader = 'primary-data/loaders/bank-of-england'
uv run --with-requirements "$loader/requirements.txt" python "$loader/load.py" --download-only
```

Загрузить готовую выгрузку в локальную БД. Вместо `<snapshot>` укажи папку, которую
напечатал загрузчик. В `data/local-check/local.env` должны быть настройки своей локальной БД:

```powershell
$snapshot = "$loader/data/<snapshot>"
uv run --with-requirements "$loader/requirements.txt" python "$loader/load.py" --snapshot $snapshot --env-file "$loader/data/local-check/local.env" --local-only
```

Сверить локальную и рабочую таблицы без записи:

```powershell
uv run --with-requirements "$loader/requirements.txt" python "$loader/transfer.py" --source-env "$loader/data/local-check/local.env" --target-env primary-data/.env --snapshot $snapshot --check-only
```

Для переноса выполни последнюю команду без `--check-only`. Данные читаются из локальной БД,
повторного скачивания с BoE нет. Готовая выгрузка нужна для проверки полноты.
Совпадающая таблица пропускается; замена выполняется целиком в одной транзакции.

Прерванное скачивание продолжается через `load.py --resume <папка> --download-only`.
Остальные параметры доступны через `--help`. SQL-проверки — в [sql/verify.sql](sql/verify.sql),
тесты — в `tests/`. Выгрузки и файлы с паролями исключены из Git.
