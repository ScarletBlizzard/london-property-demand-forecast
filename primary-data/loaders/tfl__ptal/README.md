# 🚇 Загрузчик: TfL — Public Transport Accessibility Levels (PTAL)

Наполняет таблицы `"primary".tfl__ptal_lsoa_2023` и `"primary".tfl__ptal_lsoa_2015`
индексом транспортной доступности по LSOA Лондона. Подключение к БД и пароль —
в [DB.md](../../DB.md).

Нужны `psql` и `curl`, сторонние библиотеки не требуются.

## Как пользоваться

```bash
cd primary-data/loaders/tfl__ptal

./load.sh         # оба релиза
./load.sh 2023    # один релиз: 2023 | 2015
```

Загрузка занимает секунды: оба файла вместе меньше 1 МБ. Каждый запуск полностью
заменяет таблицу. PTAL — статический срез, а не ряд: внутри релиза ничего не
досылается, поэтому догружать нечего и повторный запуск безопасен. Если
`Last-Modified` в источнике не изменился, файл заново не скачивается.

Параметры подключения берутся из общего [db.env](../../db.env). Чтобы залить в другую
базу, переопределите `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER` в окружении.

## Что загружается

| Релиз | Таблица | Строк | География | Лицензия |
| --- | --- | --- | --- | --- |
| 2023 | `tfl__ptal_lsoa_2023` | 4 994 | LSOA 2021 | OGL v3.0 + атрибуция OS |
| 2015 | `tfl__ptal_lsoa_2015` | 4 835 | LSOA 2011 | OGL v2.0 |

Рабочий признак — **релиз 2023**. Релиз 2015 рассчитан по периоду 2008–2014 и не
знает ни Elizabeth line, ни продления Northern line, ни Barking Riverside; он нужен
только чтобы сопоставить два среза между собой.

Берём уровень LSOA, а не боро: до боро всегда можно свернуть запросом, обратно —
нет. На портале TfL боро-агрегации и нет, есть только сетка 100×100 м, LSOA, MSOA
и ward. LSOA проектируются под примерно равное население (~1 500 человек), поэтому
невзвешенное среднее по LSOA почти совпадает со средним, взвешенным по населению.

Индексы отдельным файлом не выносим: таблицы по 5 тысяч строк, первичного ключа по
коду LSOA достаточно, и он объявлен прямо в `ddl_*.sql`.

## Подводные камни

**Колонка `borough` в релизе 2023 битая — не используйте её.** Атрибуция расходится
у 434 LSOA из 4 994 (8,7%), всегда на соседний боро: `Lambeth → Southwark`,
`Hounslow → Richmond upon Thames`, `Ealing → Hounslow`. Похоже на артефакт
пространственного джойна. Боро надо брать из имени LSOA:

```sql
select regexp_replace(lsoa21nm, '\s+\S+$', '') as borough,
       avg(mean_ai)                            as mean_ai
from "primary".tfl__ptal_lsoa_2023
group by 1 order by 2 desc;
```

Расхождение пересчитывается при каждой загрузке — `sql/verify_2023.sql` печатает его
в колонке «битый borough». Если число перестало быть 434, TfL что-то поправил, и
комментарии к таблице пора перечитать.

В `lsoa21nm` при этом тоже есть опечатка — `ZBarking and Dagenham` у одного LSOA,
из-за неё уникальных имён боро получается 34 вместо 33. Если нужна гарантия, боро
берётся из официального lookup LSOA21 → LAD с
[geoportal.statistics.gov.uk](https://geoportal.statistics.gov.uk).

**Разницу релизов нельзя трактовать как изменение доступности.** Она смешивает
новую инфраструктуру с сокращением автобусного обслуживания после пандемии и
возможными правками методики. Контрольный пример: у Wandsworth AI падает на 13%,
хотя в сентябре 2021 там открыли две новые станции Northern line. Для временной оси
надёжнее кодировать события руками: Elizabeth line (24 мая 2022), продление Northern
line до Battersea (20 сентября 2021), Barking Riverside (июль 2022).

**Границы LSOA между релизами разные** — 2011 против 2021. Напрямую по коду сходится
4 659 LSOA из 4 835; для полного сопоставления нужен lookup LSOA11 → LSOA21 с того
же geoportal.
